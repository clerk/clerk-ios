# Native request metadata audit

The standalone host now supplies its actual package release (`Clerk.sdkVersion` / `CLERK_SDK_VERSION`) during initialization. Shared TypeScript constructs the corresponding `x-ios-sdk-version` / `x-android-sdk-version` header. Previously the embedded runtime sent the placeholder `next`. The low-level runtime accepts an optional version; omitting it omits that header, and malformed values fail before HTTP.

The shared credential transport also adds `_is_native=1`, `x-mobile: 1`, and the stored Authorization credential. The three shared version tests cover both platforms, omission, and malformed values. The packaged iOS and Android API proofs assert the real version and native markers on startup requests. The iOS contract suite passes 48 tests and the Android packaged API suite passes five.

This is not a claim to preserve every old native header. The iOS audit read all thirteen tests in `ClerkHeaderRequestMiddlewareTests.swift`: token presence/absence and hydration without per-request storage, queued identity capture, client-ID presence/absence/skip markers, native response-generation properties, concurrent tokenless-startup generation, device ID, device type, and device/app metadata. Its old queued identity/startup and client-ID assertions remain retained for the identity audit. The new shared credential transport currently reads secure storage per request; the removed Swift hydrated-token cache is not preserved.

The old native client-ID checkpoint and skip-header protocol is absent; the core uses its own client and credential epoch. The old device identifier and Apple device/app headers are also currently absent. Their backend effects and continuity requirements still need review before claiming equivalent device reporting. Android's old device UUID was installation-persistent and its storage/attestation uses require a separate audit. Neither replacing the version header nor passing the startup proof settles those behaviors.
