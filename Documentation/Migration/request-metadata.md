# Native request metadata audit

The standalone host now supplies its actual package release (`Clerk.sdkVersion` / `CLERK_SDK_VERSION`) during initialization. Shared TypeScript constructs the corresponding `x-ios-sdk-version` / `x-android-sdk-version` header. Previously the embedded runtime sent the placeholder `next`. The low-level runtime accepts an optional version; omitting it omits that header, and malformed values fail before HTTP.

The shared credential transport adds `_is_native=1` and the stored Authorization credential. The Apple host reports a boolean `isMobile` during initialization: false on macOS and Mac Catalyst, true on other Apple targets. TypeScript constructs `x-mobile: 0` or `1` from that fact. An omitted value defaults to `1` for existing mobile hosts, including Android; non-boolean values fail before HTTP. The SDK-family identifier stays `ios` on Apple desktop targets, so those requests still carry `x-ios-sdk-version`.

This is not a claim to preserve every old native header. The iOS audit read all thirteen tests in `ClerkHeaderRequestMiddlewareTests.swift`: token presence/absence and hydration without per-request storage, queued identity capture, client-ID presence/absence/skip markers, native response-generation properties, concurrent tokenless-startup generation, device ID, device type, and device/app metadata. The [complete request construction audit](request-construction-test-audit.md) records the changed startup and client-ID contracts and retires this old middleware file. The new shared credential transport currently reads secure storage per request; the removed Swift hydrated-token cache is not preserved.

The old native client-ID checkpoint and skip-header protocol is absent; the core uses its own client and credential epoch. The old device identifier and Apple device/app headers are also currently absent. Their backend effects and continuity requirements still need review before claiming equivalent device reporting. Android's old device UUID was installation-persistent and its storage/attestation uses require a separate audit. Neither replacing the version header nor passing the startup proof settles those behaviors.

The desktop distinction preserves the old iOS SDK behavior. The initial embedded core always sent `x-mobile: 1`, including on macOS. This affects server-side session activity: the checked backend [device parser](https://github.com/clerk/clerk_go/blob/33e0f8279c9b4e3d90d6e4788c67237bc6378a56/pkg/transformers/session_activities.go#L132) explicitly uses `X-Mobile` when present, otherwise falling back to User-Agent parsing. Desktop requests now send `0` while retaining native transport and credential semantics.

- Generated domain APIs and the binding contract are unchanged. The Mac Catalyst SDK build also passes. Catalyst uses the same desktop conditional; compilation does not claim a Catalyst runtime test.

A case-insensitive search of Go source at the backend revision above found no references to `x-native-device-id`, `x-device-type`, `x-device-model`, `x-os-version`, `x-app-version`, `x-bundle-id`, or `x-is-sandbox`. That is bounded source evidence, not proof that every service or edge consumer ignores those headers. Their wider effects and Android device-ID continuity are not established by this prerelease. The request construction audit retires the deleted middleware assertions with explicit wire-contract changes; it does not claim equivalent external device reporting.

Explicit native client deletion now removes a blank-Bearer credential in the shared transport, fences older responses and supports Expo read/write-only caches.
