# Authentication flow assertion audit

The [rendered iOS authentication journey](rendered-auth-journey.md) additionally verifies native identifier/code entry, error-sheet dismissal, retry and prebuilt finalization through the packaged core.

Baseline: `02f98f89a19b6c079517c9aae07df7edd0e600e5`. All assertions in the 1,541-line `Tests/Domains/Auth/AuthTests.swift` were reviewed. Its inventory omitted two multiline parameterized declarations: `signOutUsesSessionServiceSignOut` and `setActiveUsesSessionServiceSetActive`. The corrected total is 40 declarations. The file SHA-256 matched the baseline inventory before retirement.

The new public owner is the generated future resource graph and shared TypeScript helpers. `Clerk.shared.auth` and its native service mocks are removed. Low-level authentication and callback handling leave `finalize()` explicit. Prebuilt presentation uses the generated operation internally and enforces its own delivery gate; it does not reimplement session activation or verification policy.

## Import correction and callback evidence

The audit found that `NativeMagicLink.read()` interpreted any unknown or null legacy Android `state` as sign-in. Four generated-call fixtures reproduced redemption of invalid records (`UNSUPPORTED`, empty string, null and number). The importer now accepts only `SIGN_IN` or `SIGN_UP` when a legacy state is present. A rejected record is discarded before completion HTTP or ticket authentication.

The previous iOS `PendingMagicLinkFlow` decoder deliberately defaults an absent or null `kind` to sign-in; that behavior remains supported. This was checked against `Sources/ClerkKit/Domains/Auth/MagicLink.swift` at the baseline above. The Android `PendingNativeMagicLinkState` enum and `PersistentPendingNativeMagicLinkStore.load()` at baseline `1ea9f97250e9e3b266b7fbcfe37d9373e4fc393f` reject invalid enum values. The fix is in `packages/clerk-js/src/utils/NativeMagicLink.ts`, with no native interpretation of flow kinds.

Twelve added `magic-link.test.mjs` cases cover the four invalid states, both absent/null iOS defaults, incomplete sign-in and sign-up, three invalid sign-up completion responses, and a newer prepared flow racing an old completion. Incomplete attempts publish their real remaining requirements and an observable `authCallback`, clear the consumed verifier, and leave the session unselected. A sign-up flow rejects a ticket or wrong sign-up ID without issuing a sign-in/create request. Starting a newer flow fences the old completion, preserves the new verifier, and publishes no stale callback. The old implementation allowed the older result to activate while preserving the newer verifier; the selected runtime instead rejects stale work before ticket use.

Eight new packaged-engine scenarios in `EmailLinkCompletionTests.swift` and Android `EmailLinkCompletionTest.kt` verify invalid states, iOS default migration, valid Android state, remaining requirements and wrong-result rejection through generated APIs. These use raw FAPI responses and real JavaScriptCore/QuickJS execution. They are not mail-client delivery or released-app upgrade tests.

## Validation and pins

Before the importer correction, all four invalid-state shared fixtures redeemed their verifier. Both native engines reproduced the two selected invalid-state cases; the other six new native scenarios passed. With the corrected core, all 521 shared embedded tests pass (40 email-link cases, including terminal/nonterminal cleanup). Full packaged suites pass: 103 tests on macOS, 100 on iOS Simulator and 111 on Android. The 11 `AuthFlowCoreTests` pass on both macOS and iOS Simulator, including the recovered-session finalization-error gate. TypeScript checking, generation (342 types, 1,551 members, zero unsupported shapes), and reproducibility checks pass, including the Expo attached transport. The macOS runs retained existing CoreData/NSXPCConnection and linkd registry warnings without test failures.

Packaged JavaScript revision: `29de5049111f3ebcb5bea299ec3f7e4d29844cf3`. Contract SHA-256: `0f8387f260072ba6f894442b73d50afa6bda5f1205ed3c9209f5d6b1cfba16ce`. Bundle SHA-256: `11c3182aa2585c3212037e6182bf9e35dfed51f75d7cfda1f65535c07efe2e15`. Both native manifests are byte-identical and each bundle matches its recorded hash. No generated public API changed.

`AuthTests.swift` is retired after verifying its baseline hash, all 40 declaration names, shared behavior checks and packaged native checks. The remaining legacy files retain their own audits; the default legacy test target is not disabled. This work does not claim live provider authentication, actual released-app upgrades, mail-client callback delivery, physical performance or full visual UI journeys.
