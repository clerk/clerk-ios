# Request construction assertion audit

Baseline: `02f98f89a19b6c079517c9aae07df7edd0e600e5`. All assertions and helpers were read in `Tests/Networking/ClerkAPIClientTests.swift` (nineteen declarations) and `Tests/Middleware/ClerkHeaderRequestMiddlewareTests.swift` (thirteen). Their hashes and exact names are preserved in [the baseline inventory](legacy-tests.json). This audit retires exactly these two files. The separate [client-sync middleware audit](client-sync-middleware-test-audit.md) retires that file; broader core/storage suites remain separately audited work.

## Current request contract

The public API returns generated resources from an awaited `Clerk.connect`. Both platform connection implementations await runtime initialization before exposing the root; failure closes that runtime and throws. Applications cannot obtain the primary owner's auth roots while its startup request is suspended. The old synchronous global configuration, tokenless-startup takeover marker and private refresh coordinator therefore have no equivalent public call sequence. Reconnection is explicit; it does not implement the old coordinator's restart or rollback contract.

TypeScript constructs requests. Native HTTP forwards the supplied method, URL, headers and body, performs multipart encoding, and reports HTTP results. The canonical FAPI version is selected through `__clerk_api_version`, replacing the old native `Clerk-API-Version` request header. The checked backend [version middleware](https://github.com/clerk/clerk_go/blob/33e0f8279c9b4e3d90d6e4788c67237bc6378a56/pkg/apiversioning/middleware/middleware.go#L22) accepts either form and rejects requests that supply both. The source core pins `2026-05-12`; native hosts must not append the old header. `_is_native=1` replaces the old literal `true`. SDK version and desktop/mobile classification are covered by the [request metadata audit](request-metadata.md).

The new major does not expose a mutable native client, `URLProtocol` generation properties, client-ID skip markers, custom native signing/middleware, or deferred-sync response metadata. Shared credential ordering and the request guard replace the relevant in-process freshness outcomes; they do not recreate the old cross-process identity format. Live shared-session synchronization remains explicitly unavailable.

The selected transport also omits the old device/app metadata headers (`x-native-device-id`, `x-device-type`, `x-device-model`, `x-os-version`, `x-app-version`, `x-bundle-id`, `x-is-sandbox`). The backend source review found no Go references to these header names at the pinned revision; `X-Clerk-Client-Id` appears in response-header tests, with no request-header consumer found by that search. This is bounded evidence. The prerelease does not promise the old wire metadata or compatibility with any external telemetry consumer of it. Removing tests for the deleted middleware does not establish Android device-ID/attestation continuity or unchanged server device reporting. Those release limitations remain in the metadata and platform guides.

## API-client declarations

| Baseline declaration | Current behavior and evidence |
| --- | --- |
| `requestHeaders` | Generated requests use form content type when required, the core API-version query, actual native SDK version and host-provided mobile classification. `sdk-version.test.mjs`, the FAPI source URL/body suite and both packaged proof entry points check this composition. The old version-header literal is intentionally replaced, not forwarded in addition. |
| `mobileHeaderValueMatchesPlatform` | Apple initialization supplies false for macOS/Mac Catalyst and true elsewhere. Packaged macOS/iOS tests assert `x-mobile: 0`/`1`; Catalyst compilation checks the same conditional. No old dependency-container property remains. |
| `isNativeQueryParameter` | Shared transport uses `_is_native=1`; packaged proof requests and metadata tests assert it. The old string `true` is not preserved as a textual contract. |
| `getRequest` | Generated collection/resource reads issue GET. Production Apple HTTP tests also verify unchanged GET forwarding. |
| `postRequest` | FAPI constructs form bodies; generated auth/organization tests verify submitted fields and POST. The host forwards the supplied bytes. |
| `postRequestWithExplicitJSONContentType` | The public native Encodable request builder is removed. Metadata methods execute the TypeScript resource's serialization; the host's exact-byte tests cover transport without a second native serializer. This does not preserve a caller-selected arbitrary content-type API. |
| `patchRequest` | Source FAPI sends effective mutations as POST with `_method=PATCH`. Generated user/organization tests check this actual behavior. The raw HTTP capability can still forward PATCH, covered independently by the platform suite. |
| `deleteRequest` | Source FAPI uses POST with `_method=DELETE`; generated destruction, sign-out and image-deletion tests assert those requests and their results. The platform HTTP suite separately checks raw DELETE forwarding. |
| `queryParameters` | The source URL/query suite and generated pagination/filter tests verify query values. Apple HTTP checks preservation of an encoded ampersand rather than reconstructing the query. |
| `multipartUpload` | Production Apple HTTP tests verify multipart content type, boundary and exact text/binary bytes. Generated profile/logo tests verify typed upload values reaching that capability. The old test only checked POST/content type. |
| `errorHandling` | Packaged proof operations expose structured error code, parameter metadata and description. `network-failure.test.mjs` covers HTTP failures and retry policy. A host HTTP status is returned to TypeScript rather than decoded by a second native API client. |
| `failedTokenlessRequestRestartsStartupClientRefresh` | The old custom middleware failure cancelled a global startup request and scheduled a replacement. That middleware and partially configured singleton are removed. `connect` awaits initialization or throws and closes its owner; callers explicitly retry connection. No automatic takeover-restart count is promised. |
| `successfulTokenlessRequestDoesNotRestartStartupClientRefresh` | The old request could authenticate while synchronous global startup was still pending. Primary generated auth roots are obtained after `connect`; they do not race that coordinator. Shared response ordering, credential rotation and owner-terminal tests protect their own supported late-response paths. |
| `retryPreservesFirstPreparedSharedIdentityContext` | The [request retry audit](request-retry-test-audit.md) verifies a successful retry with its first credential and session. Native checkpoint counters/client-ID properties are removed. |
| `retryRestoresFrozenClerkContextBeforeCustomSigningMiddleware` | The custom native signing stage is removed. The source request prepares once and preserves its headers; no replacement callback order/count is claimed. |
| `retryIsCancelledWhenPreparedClerkIdentityChanges` | Generated and packaged tests reproduce and prevent HTTP after sign-out, including the source test for a change during backoff. |
| `retryIsCancelledWhenRequestDeviceTokenPropertyChanges` | A real credential rotation fences further transmissions. The private native request property is removed; the supported outcome is tested through resource calls on both engines. |
| `deferredClientSyncMetadataPreservesPreparedRequestAndResponseContext` | `automaticallySyncClient`, checkpoint copies, shared-session base generation, `.context(update:)` and public deferred metadata are removed. The credential/date/client acceptance queue is internal TypeScript state. Held/failed writes and response-order tests verify supported persistence-before-hydration and freshness, not the old metadata object's field values. |
| `deferredClientSyncMetadataRequiresDisabledAutomaticSync` | Neither the native response metadata object nor its automatic-sync option exists. All resource calls use the shared acceptance path; no nil metadata getter is exposed as compatibility API. |

## Header-middleware declarations

| Baseline declaration | Current behavior and evidence |
| --- | --- |
| `addsDeviceTokenHeaderWhenPresent` | Shared transport reads the client credential, distinct from a session JWT, and supplies Authorization. Shared credential tests and generated restored-credential requests check the value. |
| `adoptedIdentityUsesHydratedTokenWithoutReadingStoragePerRequest` | The old zero-storage-read optimization is removed. Current preparation reads secure storage after queued writes, and retries preserve that prepared value. This is an intentional performance/ownership difference; device performance gates still apply. |
| `appLocalRequestSnapshotWaitsBehindQueuedIdentityTransition` | Shared transport waits for pending credential writes/removals and refreshes an overlapping storage read before issuing a request. Unit tests cover both queues; generated held-write tests verify state/completion ordering. The old `x-clerk-client-id` header and native identity-operation API are absent. |
| `doesNotAddDeviceTokenHeaderWhenMissing` | The selected shared transport sends an empty Authorization value when there is no credential. It does not preserve Foundation's distinction between absent and empty request headers. Generated client-deletion/new-client tests verify that an old credential is not sent. |
| `addsClientIdHeaderWhenAvailable` | The private native client-ID request header is omitted. The client credential and core's client/session context identify requests; no direct native client assignment remains. |
| `tagsRequestWithCurrentClientResponseGeneration` | The `URLRequest` property is removed. Shared generation and credential-revision checks reject obsolete responses and stop obsolete retries through tested outcomes. |
| `storesClientResponseGenerationAsURLProtocolPropertyListValue` | The NSNumber property-list representation is removed with the native pipeline. The bridge transports a structured HTTP request, not native request checkpoint metadata. |
| `concurrentAtomicTokenlessRequestsShareStartupTakeoverGeneration` | The old takeover IDs, shared native operation queue, mutable whitespace token and global startup service are removed. Awaited connection changes the available call sequence. No generated API lets callers submit these two native takeover requests during initialization; no same-counter or service-cancellation count is promised. |
| `omitsClientIdHeaderWhenSkipClientIdHeaderIsPresent` | Both private client-ID and skip headers are removed. There is no user-facing skip-header option to consume. |
| `doesNotAddClientIdHeaderWhenClientMissing` | The selected transport omits that header regardless of client state. Missing credentials and client hydration are governed separately by the credential acceptance tests. |
| `addsNativeDeviceIdHeaderWhenAvailable` | The old device-helper conditional and header are not part of this profile. The bounded backend search and explicit wire-metadata limitation above apply; no equivalent platform identifier report is claimed. |
| `addsDeviceTypeHeader` | The old iPhone/iPad/Mac/CarPlay/TV/vision/watch/unspecified enum header is omitted. The supported mobile/desktop distinction is preserved through `x-mobile`, with its narrower meaning documented. |
| `addsDeviceInfoHeaders` | The five old device/app/sandbox headers and their presence/boolean-string assertions are removed. SDK version still identifies the SDK release. No claim is made that it replaces those app/device values. |

## Verification scope

All referenced runtime checks passed at shared core `0b97ed0a260429dda4f230e32bb7e94fde3097f4`: 543 embedded tests, 49 FAPI source tests (one existing skip and four TODO cases), and 15 shared credential tests. Native full suites passed 106 macOS, 103 iOS Simulator and 117 Android tests; Apple HTTP tests ran in those full Apple suites. The exact pin/hash and native retry evidence are in the linked retry audit. This retirement changes only documentation and removes these two obsolete test files; it does not alter the checked runtime or disable a test target.

Real device reporting, live shared-session behavior, old-major signed-in upgrades, network interruption and physical performance are not inferred from these fixture results. The client-sync assertions have their own retirement audit; the general core assertions are not retired by this audit.
