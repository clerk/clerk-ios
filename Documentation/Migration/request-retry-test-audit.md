# Request identity across retries

This partial assertion audit covers four declarations in the retained baseline `Tests/Networking/ClerkAPIClientTests.swift` at `02f98f89a19b6c079517c9aae07df7edd0e600e5`. It does not retire that mixed nineteen-declaration file or claim that its other request, startup and deferred-sync assertions are replaced.

The generated runtime reproduced a request sent after its identity became obsolete: a session reload waited for HTTP, another operation completed sign-out or rotated the client credential, and the failed reload sent a second GET with the original Authorization header. Response acceptance alone did not prevent that transmission. The Apple packaged-engine tests reproduced both cases. In the credential-rotation case, a response without client/credential data could also finish the old reload successfully; the retained response acceptance policy only applies its credential-revision check to credential/client-bearing replies.

Shared mobile request preparation now captures a synchronous identity guard alongside its frozen credential, generation and credential revision. Canonical `fapiClient` checks the guard before every fetch and before scheduling a network retry. A change during backoff is therefore checked again immediately before transmission. Preparation callbacks still run once; a retry cannot acquire a new credential for its old resource request. Requests without this optional internal guard retain their existing behavior. This is shared request policy, with no native retry state machine or custom middleware API added.

| `retryPreservesFirstPreparedSharedIdentityContext` | The old native middleware ran twice and restored frozen token/client-ID/generation/request-property fields. The canonical request prepares once and reuses its Authorization and session context. `network-failure.test.mjs` checks the unchanged credential and retry marker on a successful transient GET; packaged Apple/Android tests verify the retry returns the same usable session. Removed native checkpoint fields are not reintroduced. |

| `retryIsCancelledWhenPreparedClerkIdentityChanges` | A generated session GET now makes one transmission when sign-out finishes before its network failure is released. Shared and packaged-engine tests assert failure, no retry and an empty selected session. An additional source test changes the guard during backoff and asserts no second fetch. |
| `retryIsCancelledWhenRequestDeviceTokenPropertyChanges` | The private native request property is removed. Actual credential rotation now invalidates the prepared shared request: it fails without another HTTP transmission, preserving the rotated credential and current selected session. This is checked through generated operations and both engines. |

Android verification exposed a second defect: retry jitter creates fractional millisecond delays, but the Android timer capability parsed them as JSON integers. A rejected timer effect left the shared timeout callback unfinished. The production adapter now reads a number, clamps it to the existing supported range and converts to whole milliseconds for coroutine delay. Two direct capability tests first failed with `NumberFormatException` for `1.75` and `10000.75`, then passed for completion and cancellation. The packaged fixture uses the same numeric conversion. After correcting timers, Android reproduced the two obsolete-retry cases against the previous core, and its ordinary transient retry completed.
