# Factor value continuity

The canonical TypeScript `SignInFirstFactor` union now includes `TrustedDeviceFactor`, with strategy `trusted_device`, optional/nullable `trustedDeviceId`, and optional/nullable `safeIdentifier`. The prior Swift Factor decoder maps these server keys from `trusted_device_id` and `safe_identifier`. Both native types are generated from this declaration; there is no native factor serialization catalog.

The assertion audit reproduced lost device ID/display fields in an actual core snapshot. The broad OAuth enum alternative accepted the unknown strategy before the correct factor alternative could be selected. Adding the missing declaration alone did not fix that selection bug. The shared serializer now prioritizes recognized common string discriminators before unknown-enum fallback. This also preserves password-recovery and enterprise factor fields. A malformed recognized alternative fails instead of silently becoming an unrelated factor; future values within a valid alternative and future OAuth strategies remain representable.

The generated API diff contains the new `TrustedDeviceFactor` and an added `SignInFirstFactor` variant. Existing variant indices stay unchanged. The diff command intentionally returns its changed-signature status, requiring review of exhaustive native consumers. Compose compilation caught its exhaustive presentation mapping, which is now updated. Generic inline-factor choices exclude server device credentials: the dedicated biometric entry checks the local credential and OS capability before offering that flow. Custom consumers can inspect the complete generated factor list.

Validation: 141 embedded runtime tests, 13 generator tests, and TypeScript checks pass. Actual packaged tests verify phone defaults, trusted-device identity/display values, phone recovery IDs, enterprise connection IDs, and future OAuth values. iOS passes 47 core contract tests; Android passes five packaged tests and one Compose routing test. SwiftUI compiles and passes its ten factor-selection tests and fourteen provider-presentation tests. The generated preview fixtures were repackaged with the new contract hash. These are deterministic tests, not live device-bound authentication or provider UI proof.
