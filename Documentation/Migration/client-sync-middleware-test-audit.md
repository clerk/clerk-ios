# Client-sync middleware assertion audit

Baseline: `02f98f89a19b6c079517c9aae07df7edd0e600e5`. All nineteen declarations, assertion bodies and private helpers in `Tests/Middleware/ClerkClientSyncResponseMiddlewareTests.swift` were read. Its exact names and hash are preserved in [the baseline inventory](legacy-tests.json). This audit retires exactly that file; the dedicated shared-session, general core and storage suites retain their own unfinished audits.

The old middleware decoded arbitrary native response bytes and assigned a native client. The generated SDK executes canonical resource methods: `BaseResource` reads sibling or error-meta clients through `getClientResourceFromPayload`, while the client resource handles its own canonical response. Shared transport accepts credentials and freshness metadata before resource hydration. A null or missing client is not itself a deletion instruction. The generic decoder's acceptance of a synthetic partial resource does not promise that such a payload is valid for every generated resource operation.

## Assertion map

| `decodeClientFromResponseFieldWhenFetchingClient` | Canonical startup and foreground GET `/client` hydrate the response client. The client service audit and both packaged proof entry points verify the generated client ID and session. |

| `decodeClientReturnsNilWhenClientCannotBeDecoded` | The public/native byte decoder is removed. Source client extraction returns no client for an empty payload. Generated resource methods still validate their own result; this is not a promise to accept an empty response for every method. |
| `validatePreservesClientWhenCanonicalResponseAndClientAreNull` | The previously reproduced null-client regression is fixed in `BaseResource._baseGet`. Embedded foreground tests and packaged empty-client tests preserve client ID, selected session and credential. A null sibling does not produce a client in the source extraction helper. |
| `validateDoesNotClearClientForNonCanonicalNullFields` | The three old synthetic shapes test only client extraction. Source extraction ignores null `client`/`meta.client`, so no client update occurs from those fields. Existing resource-only and canonical-null tests cover preserved identity through valid operations; no claim is made that an incomplete synthetic session payload satisfies the new session codec. |
| `validateAppliesSignedOutClientFromRemovedSessionEnvelope` | Generated scoped/all-session removal tests check server envelopes, empty selection, remaining sessions and credential/cache consequences. The current TypeScript client owns removal; no native assignment is involved. |

The generated result has an empty client ID and nil session/user roots. A whole native client/date record and arbitrary middleware `clerk.client = nil` assignment are removed; they are not replacement persistence formats. |

Every supported response uses shared acceptance; there is no option to defer positive credential/client application. Explicit clear handling remains supported and tested. The old deferred positive response and forced native-nil assignment are intentional API changes. |
| `validateAppliesClientFromClientResponseEnvelope` | Session/organization response tests verify the selected organization and membership after a client-bearing operation, including post-await state. Headerless responses require an existing stored credential; the old request-only token property is not a replacement secure store. |
| `validateHoldsRegisteredAuthFlowBeforeApplyingCompletedSignInClient` | Core-owned native auth registration and internal-state observer callbacks are removed. No old middleware event/callback ordering API is retained. |
| `validateHoldsRefreshedActiveClientUntilAuthViewCompletes` | The UI gate handles external activation, completion once, dismissible versus root ownership and recovered-session finalization errors. It consumes generated session state; there is no native network reducer staging the client. The same eleven presentation tests run on macOS and iOS Simulator. |
| `validateIgnoresClientResponseFromStaleDeviceTokenGeneration` | Shared invalidation and credential-revision checks reject obsolete replies before hydration. Generated reset, sign-out and rotation tests cover these outcomes; native request generation properties and direct controller resets are removed. |
| `validateAppliesClientFromErrorMetaClientEnvelope` | Generated error-meta response-order tests exercise a rejected API operation that carries a client; accepted committed state is published before the error. The old request-device-token property is removed in favor of the stored client credential and shared request context. |
| `validateDoesNotClearClientWhenPayloadHasNoClientField` | A resource response without a client does not call the source client update. Generated resource-only requests remain usable with the existing client and selected session, including the successful packaged retry case. The synthetic old `/me/sessions/active` test does not establish a new endpoint or result signature. |
| `validateAtomicallyPersistsCompleteResponseAfterSharedTransportIsDisabled` | Current secure records persist the scoped credential, not the complete client/date snapshot. Shared held-write and failed-write tests verify persistence precedes hydration and failure leaves the accepted identity intact. Live shared-transport disablement and its snapshot transaction are unavailable; no old disk-client format is claimed. |
| `validatePersistsAdoptedIdentityOffMainActor` | The old injected identity store and its exact update/thread counts are removed. Default Keychain storage is an independent actor called through the asynchronous capability boundary. This establishes isolation, not a contractual physical-thread callback count. Physical startup/memory/main-thread performance gates remain required. |
| `validateAtomicallyPreservesIdentityForCanonicalNullResponse` | Packaged null-client checks preserve the current credential and live client/session state. Platform storage retains its scoped credential record; the removed whole-client snapshot's `.present`, client and date fields are not persisted anew. |

## Evidence and limits

The shared [client response](client-response-test-audit.md), [identity](identity-controller-test-audit.md), [client service](client-service-test-audit.md), [credential clear](client-credential-clear-test-audit.md), and [request retry](request-retry-test-audit.md) audits identify the reproduced defects, source fixes, exact public outcomes and changed APIs. The [authentication flow audit](auth-flow-test-audit.md) records explicit finalization and presentation-completion ownership. The Keychain implementation stores `{schemaVersion, credential}` in the new scoped record and writes a durable empty record when cleared; it does not recreate the old atomic client snapshot.

The current core is `0b97ed0a260429dda4f230e32bb7e94fde3097f4`, with unchanged binding contract and identical native bundles. Its complete suites pass 543 embedded, 106 macOS, 103 iOS Simulator and 117 Android tests. All eleven current `AuthFlowCoreTests` also pass on macOS and iOS Simulator, including external activation, completion once, failed finalization and cancellation/sign-out gates. This retirement changes only documentation and removes the reviewed legacy test file; runtime code and test-target registration remain unchanged.

Real signed-in upgrades, live shared-session/watch convergence, physical platform prompts, device performance and full visual UI journeys remain separate gates. Neither a decoder assertion nor a deterministic presentation test proves those outcomes.
