# Session service assertion audit

All 19 test declarations in retained `Tests/Domains/Auth/Session/SessionServiceTests.swift` were reviewed against baseline `02f98f89a19b6c079517c9aae07df7edd0e600e5`. The earlier file inventory counted 18 because it missed the multiline parameterized API-error test. This audit does not delete the legacy tests or repair the broader legacy test target.

| Legacy declarations | Current behavior and evidence |
| --- | --- |
| `signOut` | Generated `Clerk.signOut` sends the canonical DELETE operation for `/v1/client/sessions` using the shared POST plus `_method=DELETE` transport. On accepted empty-client response, sessions and selection are empty and old handles are stale. Embedded `session-sign-out.test.mjs` verifies the request and state. |
| `signOutWithSessionId` | With multiple sessions, the canonical scoped operation uses POST `/v1/client/sessions/{id}/remove`. Removing another session preserves the selected session. Unlike the old service, the shared cache clears globally before the request: reading the remaining session's cached template requires a new mint. The embedded test proves this distinction. |
| `signOutWithSessionIdPreservesCachedTokensWhenRequestFails` | Intentional source difference: a scoped 500 still clears both sessions' template entries. The structured error is delivered and sessions remain available through newly acquired handles. The old success-only, per-session cache policy is removed. |
| `signOutPreservesCachedTokensWhenRequestFails` | All-session removal preserves cached token results after a 500, verified by reading both sessions without additional mints. Authentication reset still invalidates old generated handles and fences persistence; preserving an old wrapper or credential write is not promised. |
| `setActiveClearsOrganizationByDefault`, `setActiveWithNilOrganizationIdSelectsPersonalAccount` | Both old bodies pass explicit nil. Generated explicit `organization: null` requests a personal account and publishes the accepted response. Omitting organization retains the existing selection. Embedded and both native SessionActivation suites cover all three option meanings. |
| `setActiveWithOrganizationId` | Generated activation verifies the organization form field, `select_org` intent, and accepted session/organization state. A template token read after switching does not return the prior organization's cached token. Exact deletion of private cache keys, including retention of other sessions' keys, is not a public contract. |
| `setActiveInvalidatesTemplateTokenBeforePublishingSessionChange` | A retained generated session reads the accepted organization on completion and mints a different template token for that organization; subsequent reads hit the new cache entry. This preserves the caller-visible requirement without requiring deletion of the old private cache key at an event callback. |
| `setActiveWithNilOrganizationIdSendsRequestWhenForcedOrganizationSelectionIsEnabled` | Intentional difference: the canonical force-organization-selection policy returns without HTTP and preserves the current organization. An embedded generated call verifies this behavior. |
| `setActiveWithOrganizationIdPropagatesAPIErrors` | Both parameter cases, 401 `unauthorized_organization` and 403 `not_a_member_in_organization`, preserve the selected organization and cached template token and deliver structured errors. The 401 test exposed swallowed rejection in shared `setActive`; explicit organization requests now propagate the failure. Source tests cover both ordinary and navigation touch. Native tests use real JavaScriptCore and QuickJS. |
| `fetchToken` | Generated `Session.getToken` derives previous token and force-origin from canonical session state, the session-minter flag, and `skipCache`. The generated request checks verify their exact serialized values. The removed native service's arbitrary previous-token parameter is not exposed. |
| `fetchTokenForFirstMintOmitsPreviousTokenAndForceOrigin` | Ordinary first mint omits both fields. An explicit `skipCache` with session minter enabled sends force-origin even without a previous token. Five embedded mint-policy cases distinguish this option behavior and the disabled flag. |
| `fetchTokenWithTemplate` | The generated request uses `/tokens/firebase` with no organization, token, force-origin, or tab-state form fields, even when the public options include an organization and bypass cache. Logging safeguards are audited separately in `http-test-audit.md`; the removed `shouldLogClerkBodies` flag is not a generated field. |
| `startVerification`, `prepareFirstFactorVerificationPasskey`, `prepareFirstFactorVerificationEnterpriseSSO`, `attemptFirstFactorVerificationPasskey`, `attemptSecondFactorVerificationTOTP` | The complete request/state and typed passkey mapping is recorded in `session-verification-test-audit.md`. Arbitrary native passkey JSON strings are replaced by the platform credential path. |
| `testRevoke` | Generated `User.getSessions` followed by `SessionWithActivities.revoke` verifies POST `/v1/me/sessions/{id}/revoke`, returned state, selected/other-session outcomes, and errors in embedded and both native suites. See `session-verification-test-audit.md`. |

The session-cache follow-up also verifies concurrent template requests and a cache hit for a nonselected session still present in `Clerk.sessions`. This differs from using a stale handle after removal. Snapshot-hydration details still listed in `token-cache-test-audit.md`, real OS flows, live service acceptance, and signed-in old-major upgrades remain separate work.

The 401 fix and current package validation are recorded in [organization activation](organization-activation.md#rejected-authentication-status-follow-up). This audit adds no second native session algorithm and retires no legacy test file.
